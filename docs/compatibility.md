# 兼容性与验证范围

检查日期：2026-09-23。

CodeX视频壁纸面向 macOS 上的 CodeX 桌面客户端。最低维护基线为 `26.915.31945`，验证范围已扩展到 `26.917.51856` 和 `26.917.71314`。新版适配保留前两版规则。

本轮补齐项目环境栏与文件附件卡片适配，并重跑三版界面回归。下文单独标明首轮与历史验证，避免将其视为本轮重测或完整真实页面验收。

## 版本矩阵

| CodeX 版本 | 本轮隔离验证 | 结果与边界 |
| --- | --- | --- |
| `26.915.31945` | 独立页面加载对应版本 CSS，运行修复后的渲染器，重跑 19 项界面与交互检查 | 19 项通过；未重新安装或启动旧版真实客户端。 |
| `26.917.51856` | 对应版本 CSS 下重跑 19 项界面与交互检查，新增 7 项项目环境栏 / 附件组件检查 | 19 + 7 项通过；未重新安装或启动旧版真实客户端。 |
| `26.917.71314`（build `10954`） | 对应版本 CSS 下重跑 19 项界面与交互检查，新增 7 项项目环境栏 / 附件组件检查 | 19 + 7 项通过；当前客户端效果已由用户检查并接受；不代表全部页面已验收。 |
| 其他版本 | 未纳入上述验证 | 不保证所有更早或未来版本兼容；客户端改变窗口结构、样式或调试接口时可能需要适配。 |

19 项界面回归包含整块侧栏玻璃、聊天与设置页、文字层级、输入光标、选区、焦点、链接与差异色、暂停继续、页面切换保持同一视频层、移除恢复。测试使用合成视频，不包含私人视频或真实对话。

## 新版截图问题与补测

用户提供的 `26.917.71314` 真实截图暴露了首轮独立页面遗漏的两类组件：

- 输入框上方的项目 / 本地 / 分支栏：浅色底未随壁纸适配，浅色文字难以辨认。
- 文件附件卡片：保留白色底，文件名等浅色文字对比不足。

当前源码为项目环境栏补充独立玻璃底色与文字配色，将附件界面的不透明底色改为透明；附件预览图、点击层与删除按钮保持原有行为。

新增的 [组件回归脚本](../tests/composer-surfaces.mjs) 在隔离 Chrome 中加载本机 CSS 快照目录，不分发官方资源。修复前代码在同一项目环境栏检查中失败，修复后两版各 7 项全部通过；这确认了测试能复现并检出此次问题。

本轮简要结果见 [composer-compatibility-results.json](composer-compatibility-results.json)。没有自动控制真实账号 UI；用户已检查当前效果并同意发布。更换本地源码后，需在壁纸菜单先选 `4` 关闭，再选 `1` 启用；Brew 升级后重新运行命令可切换旧后台。

## 连接、生命周期与恢复

下表为原批次已完成的验证记录。新版首轮另通过 11 组连接检查、7 项既有 core / upgrade 测试与 4 组窗口守卫检查，包含两版旧版本分别升级到 `26.917.71314` 的隔离模拟；当时壁纸自身状态为 `playing`、`connected=true`、无错误且心跳新鲜。本轮组件修复未重跑连接与生命周期检查，运行状态也不代表本轮修复已在真实客户端生效。

| 场景 | 已验证行为 | 验证方式 |
| --- | --- | --- |
| 重复进入控制台 | 等待本次请求后的新确认；复用正常后台；不把缓存状态当作新连接成功 | 隔离真实后台进程与模拟客户端 |
| 并发启动、重复关闭 | 同一状态目录只保留一个后台；关闭等待清理；重复关闭安全 | 隔离后台进程 |
| 临时连接断开 | 返回重连状态，重新发现窗口并恢复播放 | 当时控制器主循环，替换 OS/网络 I/O |
| 检测到版本更新 | 识别版本变化；客户端退出后带本机连接参数重开一次，收到窗口/视频确认后才报成功 | 当时控制器主循环的版本切换模拟 |
| 普通退出 CodeX | 等待短暂重开窗口后结束壁纸后台，不持续强行启动 CodeX | 当时控制器主循环模拟 |
| CodeX 已开但没有调试端口 | 显示等待/重启需求；只有用户明确确认才请求退出客户端 | 连接与终端交互模拟 |
| 页面重载 | 缺失视频层时重新挂载；传入已记录的片段索引与时间可恢复播放位置 | 隔离 Chromium，真实页面重载 |
| 隐藏与重新可见 | 隐藏时暂停；恢复可见时继续；用户主动暂停的状态仍保留 | 隔离 Chromium，可见性事件 |
| 长时间休眠后恢复 | 时间跳跃、socket 保留/断开均能重新响应；旧层被超时清理后能够再次挂载 | 控制器时间跳跃模拟，以及隔离 Chromium 渲染器看门狗实际清理/重挂载 |
| 旧视频部分/全部丢失 | 部分丢失跳过，全部丢失仍能进入菜单；原选择记录保留 | 隔离文件移动/删除与后台恢复 |
| 损坏的新视频 | 不提前丢弃旧配置；解码失败后回滚之前的视频与暂停状态 | 模拟后台和隔离真实视频解码 |
| PID 被复用、其他应用占端口 | 不向无关 PID 发控制信号；拒绝非目标进程或非回环地址 | 隔离进程及端口归属单元检查 |

**上述批次均未在正在工作的真实 CodeX 上触发休眠、自动更新或退出重开。** 没有自动控制真实账号 UI，也没有让电脑真正睡眠或重新安装旧版客户端。模拟通过证明了已覆盖的恢复分支，不能排除特定 macOS、电源管理或客户端更新器的差异。

普通退出后，再次使用时运行 `codex-wallpaper`。本工具当前不注册登录自动启动，也不会在用户主动退出 CodeX 后持续拉起应用。

## 视频与资源

以下为原批次检查结果，其中 `26.915.31945` 与 `26.917.51856` 各通过 6 项过渡检查。本轮未重跑过渡与完整资源检查：

- 多视频依靠真实播放结束事件按顺序循环，复用一个视频节点；同时最多一个当前视频 Blob URL。
- 自动换段使用 600 毫秒叠化；过渡结束、隐藏或关闭时释放临时快照。
- 减少动态效果偏好下直接切换；单视频原生循环不额外创建过渡。
- 稳定心跳请求小于 500 字节；不会重复注入完整渲染器、重写样式或扫描整个界面。
- 固定文字色模式没有定时取色；自动取色按需启停。
- 这些检查验证资源生命周期和重复工作的避免，不是整机功耗或长期内存压测。

## 本轮结论

当前源码已补齐 `26.917.71314` 项目环境栏与附件卡片适配，三版各 19 项界面回归以及两版各 7 项组件补测通过，保留前两版支持。用户已检查当前客户端效果并接受，尚未验收所有真实页面。

本轮修复由 **`0.1.1`** 分发，`0.1.0` 不包含这两处修复。 原批次机器结果保存在 [compatibility-results.json](compatibility-results.json)，其中源码哈希与 `26.917.51856` 运行状态属于历史记录。Homebrew 安装、升级持久性及公开发行属于独立验证与发布步骤，不由此报告替代。

本报告不携带官方客户端提取资源、用户本地路径、用户项目、视频文件名或聊天内容。
